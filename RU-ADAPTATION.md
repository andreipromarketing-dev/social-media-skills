# Соцсети РФ — адаптация форка LinkedIn-скиллов

Форк [skills для LinkedIn] адаптирован под площадки пользователя:
**ВКонтакте, MAX, Telegram, TenChat**. Среда исполнения — **opencode** на ноутбуке
(формат SKILL.md совместим нативно; браузерная автоматизация — через установленный
browser-скилл opencode).

## Что добавлено (новые скиллы)

| Скилл | Назначение |
|---|---|
| `skills/social-media-ru/` | Роутер + база знаний: платформенные карты и playbook |
| `skills/crosspost-adapter/` | Один текст → N несовпадающих версий по картам площадок |
| `skills/vk-publisher/` | Публикация в ВК через официальный API (`wall.post`, скрипт без зависимостей) |
| `skills/telegram-publisher/` | Публикация в TG через Bot API (`sendMessage`/`sendPhoto`) |
| `skills/browser-publisher/` | Публикация там, где API нет (MAX, TenChat) или нужны UI-форматы (опросы, отложенные посты) — через browser-скилл opencode |

## Платформенные карты

`skills/social-media-ru/references/platforms/`:

- `vk.md` — документировано частично, требует браузерной проверки («под кат», пути)
- `telegram.md` — документировано частично (Bot API), требует проверки
- `max.md` — ⚠️ публичного API и готовых решений на GitHub нет; карта = гипотезы, обязателен разведочный браузерный прогон
- `tenchat.md` — ⚠️ API для постинга нет; то же самое
- `_TEMPLATE.md` — шаблон для новых площадок (OK, Дзен, RU.Studio)

Общий регламент (реестр площадок, порядок адаптации, маршрутизация API/браузер,
тона двух направлений, анти-копипаста, актуализация карт) —
`skills/social-media-ru/references/platform-playbook.md`.

## Два направления работы зашиты в playbook (раздел 4)

1. **«ЮгСпецСети»** (агентство автоматизации бизнес-процессов): деловой тон, кейсы «было → сделали → стало»; основные площадки — TenChat, VK, Telegram.
2. **«Союз танкистов России»** (ветеранская организация): уважительный официально-тёплый тон, памятные даты, встречи, обращения; основные площадки — VK, MAX, Telegram.

## Изменения существующих скиллов
- `post-writer`: добавлен шаг «Platform check» — читать карту целевой площадки перед финализацией поста, маршрутизация в crosspost/publishers.
- `post-formatter`: аналогичная сноска про лимиты RU-площадок.
- Остальные LinkedIn-скиллы (hook-generator, quote-post, reels-scripting и т.д.) работают как генераторы мастер-текста; площадка выбирается на этапе адаптации. Полностью LinkedIn-специфичные (`pinned-comment`, `profile-optimizer`) можно не использовать или переделать позже.

## Журнал изменений
Все скиллы после публикаций пишут в `brand/changelog.md`; расхождения с реальностью правят карты.

## Быстрый старт (что сделать пользователю)
1. Заполнить `brand/accounts.md` ссылками на сообщества/каналы (скиллы сами спросят, когда придёт время).
2. Для ВК-публикации через API: создать ключ сообщества (права `wall`) и задать переменную окружения `VK_TOKEN`. Без токена — путь через browser-publisher.
3. Для Telegram: создать бота у @BotFather, добавить админом канала, задать `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
4. Первый запуск: сказать агенту «сделай разведочный браузерный прогон по MAX и TenChat и обнови карты» — закроются TODO-секции карт.
5. Рабочий цикл: «напиши пост про …» → post-writer → «разложи на площадки» → crosspost-adapter → подтверждение → публикация.

## Про готовые решения на GitHub (итоги поиска)
- ВКонтакте: vk-api-обёртки и MCP-серверы существуют (full-vk-mcp, vk-community-mcp); наш путь — собственный лёгкий скрипт на официальном REST API без зависимостей, MCP опционально.
- Telegram: chigwell/mcp-telegram и др. — зрелые; наш путь — прямой Bot API, MCP опционально.
- MAX и TenChat: готовых интеграций нет ни на GitHub, ни официальных API → только браузерная автоматизация (browser-publisher) либо платные шлюзы рассылки (например, Postup.me/Hooppy-класса сервисы) при появлении таких у этих площадок.

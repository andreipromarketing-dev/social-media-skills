# Platform Playbook — как работать с площадками проекта

Этот файл — «диспетчерская» для всех скиллов, которые пишут или публикуют контент.
Он говорит, КАК выбирать площадку, читать её карту и адаптировать текст.
Факты О ТОМ, что можно и нельзя на площадке, живут только в картах:
`references/platforms/vk.md`, `telegram.md`, `max.md`, `tenchat.md`.

## 1. Реестр площадок проекта

| Площадка | Карта | Путь публикации | Роль в проекте |
|---|---|---|---|
| ВКонтакте | platforms/vk.md | API (wall.post) или браузер | Приоритет №1. Сообщества обеих организаций |
| MAX | platforms/max.md | Только браузер | Приоритет №2. Официальные анонсы, госсегмент |
| Telegram | platforms/telegram.md | Bot API или браузер | Быстрый контакт с текущей аудиторией |
| TenChat | platforms/tenchat.md | Только браузер | Деловой личный бренд (ЮгСпецСети) |

Конкретные аккаунты/сообщества (ссылки, id, права) — в `/workspace/brand/accounts.md`.
Пока файл не заполнен ссылками пользователя — любой скилл обязан спросить их, а не выдумывать.

## 2. Порядок адаптации текста под площадку (используется crosspost-adapter)

Для каждой целевой площадки выполнить по шагам:

1. **Прочитать карту** `platforms/<slug>.md` целиком. Не полагаться на память модели о площадке.
2. **Проверить лимиты**: длина текста, хештеги, ссылки, медиа. Если пост не влезает — сокращать по приоритету: детали → примеры → второстепенные тезисы; крючок и главный вывод не трогать.
3. **Применить форматирование площадки**: убрать Markdown там, где его нет; привести хештеги к нужному количеству; ссылки — согласно карте (комментарий/отдельное сообщение).
4. **Подогнать тон под аудиторию площадки** (см. раздел 4).
5. **Отметить статус верификации карты**: если карта помечена `предположение`, предупредить пользователя, что правила могут отличаться, и после публикаций обновить карту.

## 3. Маршрутизация: API vs браузер

- Есть документированный API + токен у пользователя → API (vk-publisher / telegram-publisher).
- Нет API (MAX, TenChat) или нужен сложный UI-формат (опрос, отложенный пост, карусель) → browser-publisher поверх browser-скилла opencode.
- Правило безопасности для обоих путей: **публикуется только предварительно подтверждённый текстом пользователя вариант**. Черновик → показать финальный текст → явное «да» → публикация.

## 4. Тоны по направлениям пользователя

Два рабочих направления, тон различается. Конкретные формулировки — в voice-файлах (заполняются через voice-builder), здесь — каркас.

### Направление A: «ЮгСпецСети» (агентство автоматизации бизнес-процессов, yugspecseti.rf)
- Аудитория: владельцы и руководители малого/среднего бизнеса на юге РФ.
- Тон: деловой, практичный, с кейсами и цифрами («было → сделали → стало»). Меньше пафоса, больше выгоды.
- Площадки: TenChat (личный бренд), VK (сообщество агентства), Telegram (клиенты/партнёры).
- Типовые рубрики: кейсы автоматизации, разборы процессов, ответы на вопросы клиентов, анонсы услуг.

### Направление B: «Союз танкистов России» (общественная ветеранская организация)
- Аудитория: ветераны, члены организаций, патриотические сообщества, местные власти.
- Тон: уважительный, официальный-тёплый, без коммерции и без сленга. Уместны обращения «уважаемые товарищи». Акцент на памяти, преемственности, конкретных делах организации.
- Площадки: VK (основное сообщество), MAX (официальные анонсы), Telegram (оперативные новости).
- Типовые рубрики: новости организации, поздравления и памятные даты, встречи и мероприятия, протоколы/обращения, благодарность ветеранам.

## 5. Кросспостинг без копипасты

Один инфоповод → N разных текстов, а не один текст на всех.
Обязательная проверка перед публикацией серии: тексты не должны совпадать дословно между
площадками (риск анти-спама в ВК и блокировок в молодых мессенджерах).

## 6. Актуализация карт

После каждой браузерной публикации, если обнаружено расхождение с картой:
1. Исправить соответствующий пункт карты.
2. Обновить `last_updated` и `confidence` в frontmatter карты.
3. Если правило было критичным (лимит, блокировка) — добавить запись в `/workspace/brand/changelog.md`.

Раз в месяц (или по команде «обнови платформенные карты») — прогонять TODO-секции карт через browser-скилл и закрывать непроверенные пункты.

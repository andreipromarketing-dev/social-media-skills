# MAX — платформенная карта

> ⚠️ MAX — молодой российский мессенджер. Публичного Bot API и официальной
> документации по публикациям на момент составления карты НЕТ (готовых решений
> на GitHub тоже не найдено). Поэтому путь автоматизации — браузерный скилл
> (browser-publisher + browser skill opencode). Все пункты ниже — гипотезы,
> которые нужно подтвердить первым же браузерным прогоном и обновить карту.

## 1. Публикация
- Веб-версия: max.ru (вход по номеру телефона, подтверждение кодом).
- Форматы: личные чаты, группы, публичные «каналы/сообщества» внутри мессенджера (статус поддержки уточнить).
- Медиа: фото/видео из интерфейса; API-загрузка недоступна → только браузер.

## 2. Форматирование текста
- Ожидается plain text + эмодзи; Markdown-разметка скорее всего отсутствует или ограничена (проверить).
- Хештеги: наличие и кликабельность проверить. Если не работают — теги писать текстом или не использовать.

## 3. Лимиты
- Неизвестны. Замерить при браузерном прогоне: максимальную длину сообщения, размер фото, поведение длинного текста.

## 4. Алгоритм и поведение аудитории
- Аудитория: российские пользователи, переходные из Telegram/VK; контент — преимущественно новостной и локальный.
- Для ветеранской организации MAX может быть площадкой официальных анонсов (госсегмент). Уточнить по факту регистрации сообщества.

## 5. Чего избегать
- Массовых однотипных сообщений (анти-спам молодого сервиса обычно агрессивнее).
- Автоматизации через неофициальные клиенты до появления официального API — риск блокировки номера.

## 6. Отличия от других площадок проекта
- Единственная площадка проекта БЕЗ документированного API → всегда идёт через browser-publisher.
- Текст адаптируется как самый консервативный вариант: без разметки, без хештегов, если они не подтверждены.
